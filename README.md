# 내 방식 QR (My Way QR)

키오스크 앞에서 망설이는 사람을 위해, **휴대폰에 한 번 저장한 내 방식**(큰 글씨·또렷한 색·쉬운 말·천천히 읽어 주기·큰 버튼·한 화면에 한 가지씩)대로 주문 화면을 바꿔 보여 주는 시제품입니다.

- 시연: https://tiger3c.github.io/my-way-qr/ — [한 기기로 체험](https://tiger3c.github.io/my-way-qr/demo.html) · [내 방식 정하기](https://tiger3c.github.io/my-way-qr/my.html) · [키오스크 화면](https://tiger3c.github.io/my-way-qr/kiosk.html) · [운영자 화면](https://tiger3c.github.io/my-way-qr/admin.html)
- 2026 AI 라이프 솔루션 챌린지(산업통상부·한국산업기술기획평가원) 응모용 시제품 — 「AI 라이프 아이디어 챌린지」 수상 후보작 「내 방식 QR」을 구현했습니다
- 가상 매장 「카페 한모금」과 가상 메뉴 30개로 시연합니다(실존 매장·상표 아님). 주문·결제는 실제로 이루어지지 않습니다

## 흐름
1. **내 방식 정하기**(휴대폰): 필요한 기능만 켭니다. 장애 여부·병명은 묻지 않고 기능 코드만 저장하며, 저장 위치는 그 휴대폰 브라우저 안(localStorage)입니다
2. **키오스크 QR 찍기**: 키오스크의 「내 방식으로 주문」 QR을 휴대폰 카메라로 찍습니다(못 찍으면 네 자리 번호 입력)
3. **내 화면으로 주문**: 같은 메뉴·같은 가격이 내 방식으로 나옵니다. 고를 것은 하나씩 묻고, 결제 전에 한 번 더 확인하고, 언제든 「직원 부르기」를 누를 수 있습니다

## AI가 하는 일
- 매장이 메뉴를 등록할 때 **한 번**, AI(Qwen2.5-1.5B-Instruct)가 메뉴 설명과 옵션 이름을 **쉬운 말**로 바꿉니다
- 결과는 규칙 검사(v0.4: 숫자 금지 — 아라비아 숫자와 '세 번'·'천 원' 같은 한글 수사, 원문에 없는 재료 — 닫힌 재료 어휘로 판정·대체 우유(두유·귀리 등)·원문 재료나 알레르기 성분을 '없다'고 쓰기, 원문에 없는 건강·효능·식이·안심·가격·순위 주장, 빠진 주재료·카페인 정보, 온도 함정, 지어낸 조리법, 옵션 개수·뜻(뒤집기 포함), 남은 외래어, 분류, 명령문, 길이, 특수 문자)를 통과한 것만 쓰고, 통과하지 못하면 다시 한 번 만들고, 그래도 안 되면 **쉬운 낱말로 바꾼 매장 설명**(용어 사전), 그것도 어색하면 **매장 설명 그대로** 씁니다
- 메뉴 이름·가격·알레르기 정보는 AI가 건드리지 않고 매장 원본 값을 그대로 보여 줍니다
- 알레르기: 매장이 '알레르기:'를 적은 메뉴는 그 글 그대로, 적지 않은 메뉴는 **메뉴 설명에 적힌 재료 낱말**(우유·밀크·라떼·크림·치즈·버터·요거트 → 우유, 밀가루·빵 → 밀 등 고정 표)로 성분을 표시하고 「메뉴 설명에 적힌 재료로 표시했어요. 소스·시럽 성분은 매장에 확인하세요」를 함께 적습니다. 낱말도 없으면 「알레르기 유발 성분이 적혀 있지 않아요 — 걱정되면 직원 부르기」. 모든 모드(한 화면에 한 가지씩 포함)에서 메뉴를 고르면 설명·알레르기 확인이 먼저 나오고, 결제 전 확인에도 다시 나옵니다(메뉴 30개 × 모드 자동 점검)
- 손님 휴대폰에서는 AI를 돌리지 않습니다(저장된 결과를 바로 보여 줌). 손님 설정은 그 휴대폰 안에만 저장하고 서버로 보내지 않습니다(한 기기 시연 화면은 주소의 # 뒤에 기능 코드만 붙임)
- **지금 시연의 결과**(`assets/easy-hanmogeum.json`, 규칙 v0.4): 같은 모델(q4_k_m)을 개발 PC의 CPU(llama.cpp)에서 돌려 미리 만든 출력을 v0.4 규칙으로 다시 판정한 것입니다(모델은 다시 돌리지 않음) — 30개 중 AI 쉬운 말 13개, 원문 유지 17개(v0.3의 16개 중 '시럽'·'휘핑'·'비엔나' 같은 외래어가 남은 3개가 새 규칙에 걸림). 운영자 화면의 **브라우저 안 실행(WebLLM·WebGPU)**은 WebGPU가 있는 기기용 기능으로, 아직 실행 기록이 없습니다
- 규칙 시험(v0.4) — 두 가지를 나눠 적습니다
  - **설계 세트**(모의 심사에서 나온 틀린 문장·맞는 문장 83개, 규칙을 고칠 때 씀): 틀린 문장 67개 중 66개 차단, 맞는 문장 16개 모두 통과. 이 세트에 맞춰 고쳤으므로 실제 실력보다 높게 나옵니다
  - **평가 세트**(규칙을 고정하고 SHA256을 기록한 뒤 새로 쓴 34개, 규칙 수정에 쓰지 않음): 틀린 문장 24개 중 **22개** 차단(v0.3 규칙은 14개), 맞는 문장 10개 모두 통과. 놓친 것: '이 집 대표 커피'(순위 주장), '오늘은 값을 덜 받아요'(가격 주장). 평가 세트도 규칙을 만든 Claude가 썼으므로 완전히 독립된 시험은 아닙니다
  - 맞는 문장을 잘못 막은 예: 처음 보는 메뉴 '레몬 마들렌'을 '마들렌 과자'로 쓴 문장('과자'가 원문에 없는 재료로 걸림 — 막으면 매장 설명 그대로 나가므로 위험 쪽은 아님)
- 용어 사전은 Claude(생성형 AI)가 원문 뜻과 대조해 정리했고, 사람(당사자·전문가) 검수는 아직 하지 않았습니다

## 한계(시제품)
- 키오스크와 휴대폰 사이 **실시간 연결이 없습니다**. 「한 기기로 체험」 화면 안에서만 주문·직원 호출이 키오스크에 표시됩니다(실제 서비스에서는 키오스크 쪽 연동이 필요). 키오스크는 휴대폰이 보낸 합계를 믿지 않고 자기 가격표로 다시 계산하며, 다르면 경고합니다
- 재료 낱말로 정한 알레르기 표시는 메뉴 설명에 적힌 낱말만 봅니다. 소스·시럽·토핑의 숨은 성분은 모르므로 「매장에 확인」을 함께 적습니다
- 시각장애인이 키오스크의 QR을 찾는 방법(음성 안내 버튼·이어폰 잭·점자 안내)은 실제 기기에서 할 일입니다. 시제품은 키오스크 화면의 「소리로 안내 듣기」(번호 읽어 주기)까지만 있습니다
- 고령자·장애 당사자 사용성 시험, 화면 읽기 프로그램(TalkBack·VoiceOver) 호환 확인은 아직 하지 않았습니다
